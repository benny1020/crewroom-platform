[기술스택·아키텍처·구현 상세](ARCHITECTURE.md)에서 모듈 관계, 데이터 모델, 상태 복원, 업무·실행·기억·스킬 처리와 향후 서버 연결 지점을 설명한다. 이 문서는 반영 결과와 검증 기록을 요약한다.

## 반영한 제품 계약

| 연구의 판단 | 실제 반영한 동작 | 코드 |
| --- | --- | --- |
| 동료의 정체성과 대화를 분리 | 동료별 복수 대화 생성·전환, 대화별 제목과 공개 범위 | `app.js`의 `initializeModel`, `conversationFor`, `createConversation` |
| 에이전트 사용과 기억·대화 공유를 분리 | 나만/부서/팀 대화, 다른 개인 비서의 공유 대화 읽기 전용 열람. 개인 대화의 기억은 개인 범위 | `domain.js`의 `canReadConversation`, `memoryScopeForConversation` |
| Task와 Run 분리 | 업무별 별도 실행 ID, 설정·스킬 스냅샷, 이벤트 순서와 generation 표시 | `createRunSnapshot`, `appendRunEvent`, `executionPanel` |
| 스킬 장착과 실제 적용 상태 분리 | desired/effective 버전, 진행 실행의 고정 버전, 다음 실행 반영 | `skillBindingStatus`, `bindingFor`, `publish-skill` 처리 |
| 하네스를 교체 가능한 계약으로 둠 | 업무 방식 프리셋과 실행 프로필을 별도 설정, 예시 프로필의 미지원 스킬 실행 방지 | `RUNTIMES`, `runtimeSupportsSkill`, 비서·에이전트 설정 |
| 업무 맥락과 결과를 함께 유지 | 입력 대기·진행·결과 바로가기, QA 인계 완료 뒤에도 선택한 결과 접근 유지 | `workspaceSummary`, `officeActivity` |
| 새로고침 후 상태 복원 | localStorage에 현재 상태 저장. 실행 중 Run은 재개 대기로 복원 | `restore`, `persist`, `recoverInterruptedRuns` |
| 기억의 출처·정정·삭제 | 범위 검사 후 검색, 이력 보존 정정, 삭제·되돌리기, 절차→스킬 | 기억 보관함과 관련 폼 |

상태 스키마는 `9`, 저장 키는 `gyeot-prototype-v1`이다. 기존 스키마 `8`도 읽어 단일 팀의 구성원·역할 상태를 보완한다. 개인 대화는 기본 비공개이며, 선택한 대화만 범위를 변경한다. 공개 범위 변경으로 다른 개인 대화나 개인 기억 전체의 범위를 바꾸지 않는다.

제품 이름은 **크루룸 · Crewroom**으로 변경했다. 기존 데모 기록을 이어 읽도록 저장 키와 DOM/CSS의 `gyeot-*` 식별자는 유지한다. 화면·문서·패키지·공개 저장소의 표시 이름과 링크에는 새 이름을 사용하며, 캐릭터 생성 원본의 명세는 당시 기록을 보존한다.

## 팀원·팀장 화면 추가

회원가입의 **팀장이에요** 체크에 따라 같은 공용 팀에서 역할을 선택한다. 가입 시 개인 비서와 비공개 대화를 생성하고 팀원은 내 업무 공간, 팀장은 관리 화면으로 이동한다. 팀 생성·초대 코드·팀 전환은 없다.

팀장 화면에서 공유 업무 현황, 구성원 역할·부서, 부서 추가·수정, 공용 동료·스킬, 편집 정책과 변경 기록을 관리한다. 마지막 팀장 보호와 팀원 변경 제한을 제품 규칙 함수와 입력 처리에서 검사한다. 팀장도 다른 사람의 개인 대화·기억을 열람할 수 없다. [화면·권한·구현 상세](TEAM_WORKSPACE.md).

## 검증

로컬 환경: macOS/Apple Silicon, Node.js 26.4.0, Vite 8.3.4, Playwright 1.64.1 Chromium.

- `npm run check`: JavaScript 문법 검사, **도메인 계약 13건**, 정적 빌드 통과.
- `npm run test:e2e`: **브라우저 시나리오 23건** 통과. 기존 업무 시나리오 13건과 가입·역할·관리 화면 시나리오 10건으로 구성한다.
- 시나리오에는 개인 대화·기억 분리, 공유 개인 비서 대화의 읽기 전용 열람, 버전 고정, 새로고침 후 재개, 프로필 미지원, 답변 후 재개, QA 완료 결과 접근, 기억 정정·삭제 복구, 키보드와 모션 중단, 1280/1024px 배치가 포함된다.
- 각 브라우저 시나리오는 JavaScript page error도 검사한다.
- GitHub Actions는 커밋마다 같은 검사와 Linux Chromium 시나리오를 실행한 뒤 정적 데모를 배포한다. 현재 원격 결과는 [Actions](https://github.com/benny1020/crewroom-platform/actions)에서 확인한다.

## 미디어

`npm run capture`는 `dist/`의 빌드를 로컬 서버에서 열고 실제 버튼·양식을 조작한다. 1440×1080 스크린샷과 녹화를 만들고 ffmpeg로 GIF를 인코딩한다. [미디어 manifest](media/manifest.json)에 시각·크기·해시·page error와 시나리오를 기록한다. 캐릭터 작업 모션과 업무 재개·결과·실행 기록을 확인할 수 있다.

## 제품 서버에서 추가할 것

1. 인증된 사용자·부서·리소스 권한 검사. 브라우저 표시 정책으로 접근 통제를 대체하지 않는다.
2. Paperclip 재사용 범위와 API 우회 방지, 에이전트별 실행 홈·작업 환경·자격증명 분리.
3. DB의 원자적 업무 점유, 큐·작업자 임대·fencing, 영속 이벤트와 재접속 보완.
4. 실제 하네스의 native session·도구 승인·스킬 버전 적용 확인.
5. 원문·검색 색인·비동기 기억 정리, 정정·삭제의 의존 관계 처리.
6. 외부 기록의 idempotency·결과 대조, 실계정 통합과 장애 주입 검증.

localStorage의 시연 사용자는 실제 다중 사용자 서비스가 아니다. 여러 브라우저의 동기화, 서버 보안, 실제 실행 격리나 무제한 기억을 검증했다고 표시하지 않는다. 회원가입 체크박스는 역할별 UI 시연이며 실제 팀장 자격의 증명이 아니다.
