# 데이터가 늘어도 유지해야 할 품질

최적화의 완료 기준은 응답 속도와 메모리 사용량뿐 아니라, 같은 업무에서 필요한 기억·근거·현재 상태를 유지하는 것이다. 데이터가 커졌다는 이유로 기억을 최신 기록만으로 바꾸거나 의미 검색을 조용히 끄고 정상 결과를 내지 않는다.

## 실행 시 보호 · 0.11.1

| 상태                                        | 동작                                                                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 처음부터 embedding 미설정                   | 명시적으로 키워드 검색 사용                                                                                                                            |
| 의미 검색 성공, 일치 문서 없음              | `no_matches`로 기록. 검색 실패로 오인하지 않고 작업 가능                                                                                               |
| 설정한 의미 검색의 용량 초과                | `MEMORY_SEARCH_CAPACITY`로 중단. 새 결과·수용 가능 상태 생성 금지                                                                                      |
| embedding 연결 거절·잘못된 응답             | `MEMORY_SEARCH_UNAVAILABLE`로 중단. 키워드 답변으로 정상 완료 금지                                                                                     |
| 원문 embedding 누락·실패·진행 중·구버전     | `MEMORY_INDEX_INCOMPLETE`로 중단. 현재 범위의 유효한 원문과 최신 profile/revision ready cache를 비교하고 검색 대상 누락을 `no_matches`로 표시하지 않음 |
| 모델이 요청한 추가 검색에서 문제 발생       | 새 결과 저장 중단. 이미 수행한 외부 호출을 없던 일로 표시하지 않음                                                                                     |
| 과거의 저하된 검색 입력 재개                | 용량/연결 문제 또는 미검증 상태를 다시 검사하고 새 실행 요구                                                                                           |
| 고정한 embedding endpoint 제거/변경         | `EMBEDDING_PROFILE_CHANGED`. 새 검색 방식으로 몰래 전환 금지                                                                                           |
| 같은 profile에서 질문/저장 벡터 차원 불일치 | `EMBEDDING_DIMENSION_CHANGED`. 검색 결과 없음으로 처리하지 않고 모델/인덱스 확인 요구                                                                  |
| 외부 요청 결과 불명                         | 기존 `DISPATCH_UNKNOWN` 복구 계약 유지. 자동 중복 발송 금지                                                                                            |

실패한 실행의 원문과 실행 기록은 보존한다. 코드 실행 중 추가 검색에서 문제가 생기면 기존 Runner 종료·checkpoint 계약으로 수정본을 보존하고 정상 결과 완료를 막는다. 신규 의미 검색은 `semanticCoverageVersion=1`의 완전검증 증거를 실행 입력 hash에 함께 고정한다. 이전 버전의 `matched`/`no_matches` 글자만으로 재개를 승인하지 않으며, 증거가 없는 기존 입력은 수정해서 승인하지 않고 새 실행을 요구한다. 이 보호는 가용성을 낮출 수 있으며, 의미 검색의 용량 확장을 대신하지 않는다. [장기 운영 한도](LONG_TERM_OPERATIONS.md)

## 검색 확장·요약·모델 변경의 완료 기준

1. 같은 원문·질문·에이전트 범위·적용 시각·문맥 예산으로 기존 버전과 비교한다. 실제 생성 품질 비교는 같은 모델/설정과 고정된 평가 자료를 사용한다.
2. 오래된 정확한 합의, 표현이 다른 질문, 정정·삭제·만료, 개인/부서/에이전트 경계, 근거가 없는 질문을 반드시 포함한다. 오래된 정답 주변에 새 잡음을 추가해도 필요한 출처가 유지되는지 본다.
3. 출처 회수·답변 근거·모름 처리·낡은 사실 사용을 항목별로 기록한다. 근거 없는 확답·권한 누출·실행하지 않은 검사의 성공 표시는 허용하지 않는다.
4. 회상·근거 품질의 회귀가 있으면 수정하거나 해당 규모의 지원을 보류한다. ANN은 근사 검색이므로 기존 정확 검색과 품질을 비교해야 한다. 속도 개선만으로 채택하지 않는다.
5. 수정본·스킬 버전·책임자·현재 결과·재작업 이유·지정 답변이 긴 대화에서도 유지되어야 한다. 원문·근거·복구 기록을 조용히 버리지 않는다.
6. 응답 지연·메모리·디스크·검색 누락률을 함께 기록한다. 검색 누락과 연결 실패를 '일치 없음'으로 합쳐서 지표를 개선하지 않는다.

검색 회귀와 합성 답변 평가는 [기억 평가](MEMORY_VALIDATION.md)·[답변 평가](ANSWER_EVALUATION.md)에 있다. 합성 프로토콜 검사와 실제 모델 품질을 구분한다. **현재 실제 생성·embedding endpoint의 품질 비교는 수행하지 않았으므로 품질 동등성을 입증했다고 주장하지 않는다.** 실제 endpoint와 평가 결과가 준비되어야 해당 환경의 품질을 승인할 수 있다.

## 인덱스 준비와 장애 복구

검색 성공과 원문 인덱스 완성은 별개다. 질문 embedding이 성공했더라도 해당 업무 범위의 원문 embedding이 덜 준비되면 실행을 완료하지 않는다. 범위 밖 비공개 자료와 유효하지 않은 의존 근거는 coverage 대상에 넣지 않는다. 준비가 끝난 원문이 없고 해당 범위에 원문 자체도 없으면 정상적인 `no_matches`다.

`docker compose exec -T worker node server/cli.js stats`의 `embeddingIndex`에서 상태·오류별 문서 수를 확인한다. 아직 pending인 원문은 캐시 행이 없을 수도 있으므로 이 개수만으로 coverage 완성을 판정하지 않는다. background indexer가 최신 원본을 준비한 뒤 책임자가 새 실행을 시작한다. 실패 후 자동 재시도는 기존 최대 3회이며, 연결을 복구해도 실패 행이 재시도 한도에 도달했다면 운영자가 해당 실패 캐시만 검토해 재등록해야 한다. 캐시는 재생성 대상이고 원문·답변·근거는 삭제하지 않는다.

이 정책 때문에 준비가 덜 된 대규모 corpus에서 실행이 중단될 수 있다. 조용히 품질을 낮추는 동작을 막았다는 뜻이며, 해당 규모의 검색 성능과 품질을 확보했다는 뜻이 아니다. 충분한 인덱싱 처리량과 확장된 검색을 구현·비교 검증해야 지원 범위를 넓힌다.
