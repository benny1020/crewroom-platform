# 크루룸 · 데스크톱 사용성 개편

> 0.4 리뷰 반영 업데이트: 대상 접수·근거 요약·QA 인계·결과 수용·역할 요청·스킬 담당·단일 업무방을 구현했습니다. 현재 계약과 23개 도메인/31개 브라우저 검증은 [확정 설계와 검증](DESIGN_IMPLEMENTATION.md)에 정리했습니다. 아래는 이전 구현·검토 기록입니다.

범위: 인터랙티브 목업. 실제 에이전트 실행과 서버 저장은 연결하지 않는다.

현재 공개 웹 프로토타입에는 아래 설계 보완 중 대화 분리·공유 범위·실행 ID·버전 상태·로컬 복원까지 반영했다. [실제 반영 내역과 브라우저 검증](IMPLEMENTATION.md)에 구현과 서버 후속 작업을 구분했다. 이 파일 아래의 기존 단일 HTML 브라우저 검증 기록도 이력으로 유지한다.

## 후속 코드 조사에 따른 설계 보완 · 2026-10-16

[공개 코드 상세 조사](OPEN_SOURCE_CODE_RESEARCH.md)의 11장에서 다음 UI 계약을 추가했다. 이 항목은 설계 보완이며 아래 브라우저에서 검증한 기존 목업 동작과 구분한다.

- 캐릭터 현황과 함께 입력·승인 대기, 진행 중 업무, 새 결과물에 바로 접근한다. 실제 서비스의 모션은 RunEvent와 마지막 갱신 시각으로 설명할 수 있어야 한다.
- 공용 에이전트 사용, 대화 열람, 기억 읽기/쓰기, 스킬 편집과 도구 실행 권한을 별도로 표시한다.
- 에이전트 설정 화면은 스킬의 장착 버전·현재 실행 버전·다음 실행 적용·미지원·적용 실패를 구분한다.
- 대화는 연결된 업무와 공개 범위를 유지하고, 개인 비서의 선택한 결과를 부서에 공유하는 동작을 제공한다.
- 반복 업무는 필요한 입력과 결과 예시가 있는 실행 양식으로 제공한다. 기억은 근거·수정 이력·공개 범위·정정/삭제를 함께 보여 준다.

## 디자인 방향

캐릭터가 일하는 네 부서 오피스를 중심 장면으로 유지한다. 따뜻한 종이색과 차분한 남색, 읽기 편한 본문 크기를 사용한다. 색은 진행·확인 대기·완료에 같은 의미로 적용한다. 모든 화면에서 메뉴 위치와 업무 시작 버튼을 유지한다.

## 우선 해결할 흐름

- 오피스의 아이콘 전용 메뉴를 다른 화면과 같은 이름 있는 메뉴로 통일한다.
- 상단에서 담당자와 스킬을 골라 업무를 맡긴다. 개인 비서는 개인 공유가 기본이다.
- 빠른 찾기에서 에이전트·작업·스킬·접근 가능한 기억으로 이동한다.
- 확인 요청에 바로 답하고 재개한다. 작업 상세에서도 질문을 진행 기록보다 먼저 보여준다.
- 스킬을 적용할 동료를 명시하고, 그 동료에게 장착·해제·실행한다.
- 기억은 관련 기억 전체부터 보여주고 출처·이력을 유지한다. 지우기는 되돌릴 수 있다.
- 대화의 반복 인사와 중복 소개를 줄이고, 작업·기억·스킬로 이어지는 동작을 가깝게 둔다.

## 참고한 패턴

[Linear Inbox](https://linear.app/docs/inbox)의 ‘주의가 필요한 일 우선, 목록에서 직접 처리’ 패턴을 참고했다. 화면이나 상표를 복제하지 않는다. 기존 프로젝트의 캐릭터와 부서 구조에 맞춰 적용한다.

## 검증 기준

1024px 및 1280px 데스크톱에서 네 부서의 여덟 에이전트와 핵심 행동을 읽고 선택할 수 있어야 한다. 업무 요청, 직접 답변, 스킬 대상 전환, 기억 검색과 삭제 복구를 실제 미리보기에서 확인한다. 키보드 검색·Escape·대화상자 초점과 모션 중단도 확인한다.

## 검증 결과 · 2026-10-16

Codex 브라우저의 실제 미리보기에서 다음 흐름을 조작했다.

| 흐름 | 확인한 결과 |
| --- | --- |
| 데스크톱 배치 | 1280px 전체 화면과 1024×900에서 네 부서·여덟 캐릭터 표시. 1024px에서 제품 영역 clientWidth와 scrollWidth가 모두 992px로 가로 넘침 없음. |
| 업무 요청 | 담당 동료·스킬을 바꿔도 입력한 요청 유지. 개인 비서로 바꾸면 공유가 해제됨. 개인 업무 T-109 생성 후 샘플 실행 완료 알림 확인. |
| 확인 요청 | O-105의 검증 범위를 목록에서 직접 선택하고 재개. 답변 완료 후 확인 요청 0건과 빈 상태 표시. |
| 스킬 대상 | 린을 선택해 회의록 정리 장착 시 2개→3개, 해제 시 2개. 실행 준비 창의 담당자 린·검증 중심 하네스·팀 공유 기본값 확인. |
| 기억 복구 | 린의 세션 갱신 기억 상세에서 출처·이전 버전 표시. 삭제 시 4개→3개, 되돌리기 후 4개와 v2 내용 복구. |
| 개인 영역 | 민지로 전환하면 로프레의 개인 업무 T-109가 검색되지 않음. 같은 ‘보고’ 검색에서 민지는 모아의 QA 보고 방식, 로프레는 루미의 보고 방식만 개인 결과로 표시. |

최종 스크립트 `node --check` 통과. HTML fragment 371,421바이트, 직접 API 호출 없음, 정의되지 않은 제품 색상 토큰 없음. 브라우저 페이지 오류 로그는 0건이었다. 검증용 뷰포트 변경은 원래 크기로 복구했다.

## 남은 제한

실제 사용자를 대상으로 한 정량 사용성 실험은 하지 않았다. 대화·업무 실행은 샘플이고, 개인 영역 분리는 목업 내 표시 동작만 검증했다. 서버 인증·권한 격리·동시 편집·영구 저장을 증명하지 않는다. 기억 검색은 기존 키워드 시연이며 무제한 기억을 구현한 상태가 아니다. 모바일은 요청 범위에 포함하지 않았다.
