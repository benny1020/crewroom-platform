# 0.8 기억 설계: 공개 자료 비교와 채택 결정

2026-10-18. 대상은 **한 팀이 같은 역할별 에이전트·스킬·업무 결과를 함께 쓰는 플랫폼**이다. 공개 제품 설명, 논문, 고정 커밋의 핵심 코드를 비교했다. 모든 프로젝트 전체를 감사하거나 비공개 알고리즘을 재현한 보고서는 아니다. [현재 구현](MEMORY_ARCHITECTURE.md) · [코드 조사 영수증](research/2026-10-18-memory/deep-audit.json)

Grok은 기본적으로 사람별 비공개 대화를 제공한다. Crewroom은 **공유 업무방이 주목적**이므로 팀이 공개한 업무방의 대화·답변을 같은 프로젝트에서 이어받고, 개인 비서는 비공개로 유지한다. 이 차이는 의도적이다. Grok의 개인 OAuth 연결과 공용 키 연결 전체, Muse의 Sentinel/authd·eBPF·사용자별 VM 전체를 구현했다고 주장하지 않는다. 현재 저장소 연결은 배포가 등록한 프로젝트와 공유 범위에 제한된 서비스 자격 증명을 사용한다.

두 서비스의 공개 문서는 기억의 내부 랭킹·추출 알고리즘을 충분히 공개하지 않는다. 따라서 아래 구현 선택의 근거는 별도의 논문과 오픈소스다.

## 이번에 선택한 운영 방식

1. 같은 PostgreSQL 안에서 원문·모든 답변 버전·핵심 기억·기억 후보·출처 ledger를 관리한다.
2. 공개 범위 필터 후 키워드와 선택적 벡터 후보의 순위를 RRF로 결합한다. 중복 본문을 제거한다. 같은 프로젝트의 공개 원문과 명시적으로 저장한 프로젝트 공통 기억은 역할을 넘어 이어받는다.
3. 모델은 원문의 정확한 인용과 함께 후보를 제안할 수 있다. 후보는 기억에 자동 편입되지 않는다. 요청자 또는 공유 기억 관리자가 저장한다.
4. 정정은 과거 기록을 바로잡는 행동이고, 새 결정은 적용 시작을 가진 후속 기억이다. 과거 원문은 남긴다. 직접 원문 읽기는 접근권이 있으면 지난 기록도 제공하며 시각을 함께 보여준다.
5. 스킬은 실행 지침이다. 기억 제안이 스킬을 자동으로 수정하지 않는다. 수용한 업무의 초안을 만든 뒤 게시하고 동료에 적용한다.

이 선택은 별도 VM·graph DB·외부 기억 SaaS 없이 단일 팀 운영과 검토 가능성을 우선한다. 벡터 캐시는 아직 JSONB exact scan이며, 큰 규모의 처리량과 실제 다국어 검색 품질은 검증이 필요하다. 지금 구성의 보편적 최적성은 주장하지 않는다.

## 0.8.1 Astra 재조사

별도 Astra 연구자가 공식 제품 문서·논문 9종과 고정 SHA 코드 4개를 다시 열어 확인했다. [독립 조사 원문](reviews/2026-10-18-astra-memory.md)과 [적용 결과](ASTRA_MEMORY_REVIEW.md)를 함께 보관한다. 공개 설명은 내부 랭킹 알고리즘의 증거가 아니며, Muse의 구현을 복제한 것으로 설명하지 않는다. AgeMem 기존 표는 v1 기준이고 재조사 시점의 abstract는 v3이므로 버전을 혼용하지 않는다.

현재 우선순위는 출처 무효화·기간·권한·동시성의 정확성이다. graph DB, 자동 사실 병합, 강화학습 기반 기억 관리와 외부 기억 서비스는 보류한다. 실제 endpoint로 평가할 때는 같은 문맥 예산에서 키워드·의미·결합 검색과 무기억 조건을 비교하고, 출처 회수율뿐 아니라 답변의 근거 일치·모름 응답·낡은 결정 사용·권한 위반·지연·비용을 분리 측정한다. 20문항의 합성 검색 결과를 실제 팀 성능으로 확대하지 않는다.
