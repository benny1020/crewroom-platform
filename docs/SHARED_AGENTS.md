# 크루룸의 주목표 · 서버에 상주하는 공용 에이전트

> 2026-10-17 변경: 현재 정책·상태·Paperclip 재사용 경계·서버 복구 계약은 [리뷰 반영 확정 설계](DESIGN_IMPLEMENTATION.md)가 기준입니다. 이 문서의 기존 구조에 추가 적용합니다.

2026-10-16 제품 목표: **주목표는 서버에 떠 있는 공용 에이전트를 워크스페이스 구성원이 함께 사용하는 것**이다. 이 문서는 제품 목표와 후속 구현의 완료 기준을 정리한다. 현재 공개 웹은 로컬 목업이며, 아래 서버 실행·동기화는 아직 구현하지 않았다.

## 이 제품이 필요한 배경

팀원마다 스킬을 따로 쓰고 세션을 개별 실행해 맥락과 결과 공유가 어렵고, 결과물 형식도 제각각이다. 공용 에이전트는 **같은 업무 기준·스킬 버전·공유 세션·결과물 형식**으로 이 문제를 해결하는 데 목적이 있다. [표준화 목적의 이슈 검토와 통과 기준](TEAM_STANDARDIZATION_REVIEW.md)은 현재 구현과 보완 제안을 구분한다.

## 팀이 함께 쓰는 대상

직속·개발·운영·QA 아래 공용 에이전트를 등록하고 서버에서 운영한다. 팀원들이 개발 에이전트 카이에게 접속하면 **같은 Agent ID의 카이**를 사용한다. 사용자마다 공용 에이전트를 복제하지 않는다.

카이의 역할·캐릭터·장착 스킬·하네스 설정·허용된 공용 기억·업무 이력은 서버에 남는다. 팀원들은 권한이 있는 공용 대화와 업무에 참여하고, 다른 사람이 남긴 맥락과 산출물을 이어서 사용한다. 요청자와 조작자는 각 메시지·업무·변경 기록에 따로 남는다.

개인 비서 커스텀은 기존 요구대로 유지하는 보조 기능이다. 공용 에이전트에게 직접 요청하는 데 개인 비서를 거칠 필요는 없다. 개인 비서의 대화·기억을 공용 에이전트에 자동 공개하지 않는다.

## 기본 사용 흐름

1. 팀 오피스에서 부서별 공용 에이전트와 현재 업무·대기 이유를 확인한다.
2. 에이전트를 열어 공용 대화에 참여하거나 새 업무 대화를 만든다. 필요한 경우 기존의 비공개 대화도 사용한다.
3. 메시지로 요청하거나 그 에이전트의 스킬을 실행한다. 작업 대상·완료 기준·공개 범위를 확인한다.
4. 서버가 요청을 접수해 실행하고, 팀원들은 같은 업무의 상태·추가 질문·산출물을 본다.
5. 다른 팀원이 맥락을 보충하거나 담당 업무를 인수해 이어간다. 실행 조작 권한과 충돌 처리는 별도 업무 정책으로 정한다.
6. 결과와 검증 근거를 업무에 남기고, 공유가 허용된 경험을 해당 공용 에이전트의 기억과 스킬 개선에 사용한다.

공용 대화에서 시작한 팀 업무와 비공개 대화에서 파생한 개인 업무는 원본 범위를 유지한다. 공용 에이전트를 함께 쓰는 것과 모든 개인 대화를 공개하는 것은 각각의 정책으로 다룬다.

## 서버에 상주한다는 의미

| 대상 | 유지할 책임 |
| --- | --- |
| 공용 에이전트 | 사용자 접속과 무관하게 같은 ID·역할·설정·스킬·기억을 유지 |
| 에이전트 운영 서버 | 항상 요청을 받을 수 있고, 실행을 관리하며 정지·장애 상태를 알림 |
| 실행 작업자 | 웹을 닫아도 접수한 업무를 수행하고, 대기·중단·실패 시 진행 상태를 보관 |
| 공유 저장소 | 대화·업무·이벤트·산출물·기억·스킬 버전의 기준 상태를 서버에 보관 |
| 웹 | 서버 상태를 읽고 조작하며, 재접속 시 누락된 상태와 이벤트를 복원 |

에이전트는 대기 중에도 서버에 등록된 동일한 동료로 남는다. 실제 모델 호출과 도구 사용은 요청·이벤트·허용된 일정에 따라 실행한다. 실행 프로세스의 구체적인 유지 방식은 하네스 검증에서 결정하되, 브라우저를 켜 둬야만 동작하는 구조는 완료로 보지 않는다.

같은 공용 에이전트는 여러 대화·업무를 가질 수 있다. 동일 업무의 상태 변경은 순서를 보장하고, 독립 업무의 실행 맥락과 작업 사본은 분리한다. 공용 기억·공동 작업공간을 갱신할 때 버전과 충돌을 처리한다. 공용 에이전트에 접근할 수 있어도 연결된 모든 외부 계정의 권한을 자동으로 얻지는 않는다.

## 화면의 우선순위

주 화면은 부서별 공용 에이전트와 팀의 공유 업무를 보여 주는 팀 오피스다. 공용 에이전트를 선택하면 대화·진행 업무·결과·기억·스킬·설정을 한곳에서 확인한다. 내 업무 공간은 내가 답할 질문과 맡긴 일을 추적하는 보조 화면이고, 개인 비서는 별도 진입점을 유지한다.

팀장은 공용 에이전트의 실행 상태·연결·하네스·스킬·부서·이용 권한과 막힌 업무를 관리한다. 개인별 비서 설정 관리가 팀장 화면의 중심이 되지 않는다. 위 내용은 후속 화면 설계 기준이며, 현재 목업의 기본 경로나 화면을 변경했다는 뜻은 아니다.

## 첫 서버 구현의 완료 기준

- 서로 다른 브라우저로 접속한 두 실제 사용자가 동일한 공용 Agent ID와 허용된 대화·업무를 본다.
- A가 공용 에이전트에게 맡긴 일을 B가 같은 업무방에서 읽고 맥락을 보충하거나, 권한에 따라 인수·재개할 수 있다. 조작자가 기록된다.
- A와 B가 모두 웹을 닫아도 서버가 업무를 실행하거나 대기 상태를 유지한다. 다시 접속하면 같은 업무와 결과를 확인한다.
- 서로 다른 요청의 입력·실행 환경이 섞이지 않으면서, 허용된 공용 기억과 스킬은 같은 에이전트에 축적된다.
- 에이전트나 서버 작업자가 재시작돼도 대화·업무·기억·스킬 버전이 남는다. 중단된 외부 작업은 결과를 확인한 뒤 복구한다.
- 화면의 작업 모션은 서버가 확인한 실행 상태와 연결된다. 연결이 끊기면 마지막 갱신 시각과 갱신 중단을 표시한다.
- 같은 업무 유형은 공용 스킬·결과 구조·표시 템플릿의 정해진 버전을 사용한다. 서버가 결과 형식을 검사하고, 버전 있는 산출물을 팀에서 검색·열람·인수할 수 있다. 형식 검사와 내용 검증은 구분한다.

이 기준을 먼저 구현하고 검증한다. 개인 비서 기능 확대와 직무 전반의 자율 수행 능력 평가는 그 이후 범위를 넓힐 때 다룬다. 각 설치는 독립 워크스페이스와 공유 저장소를 기준으로 운영한다.

실제 서버에 띄우는 구성·저장·기동·재시작·백업과 구현해야 할 배포 파일은 [배포·운영 설계](DEPLOYMENT.md)에 있다. 현재 해당 서버 코드와 배포 설정은 없으며, 공개 Pages는 웹 목업만 실행한다.
