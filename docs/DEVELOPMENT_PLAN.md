# 0.6 개발 결과

Native 행동 루프·GitLab 고정 archive·실제 Docker 파일 수정/검사·최종 코드와 검사 결합·독립 QA·실패/복원 후 checkpoint 인계·개인/공용 스킬 생성/적용/트리거·비밀번호 변경/초기화를 추가했다. 구현 계약은 [실행 아키텍처](CODE_EXECUTION.md), 증거는 [검증 보고서](SERVER_VERIFICATION.md)가 기준이다. 모델·저장소 URL과 프로젝트용 toolchain 이미지는 각 배포에서 설정하고 검증한다. 아래 0.5 계획은 개발 이력이다.

# 실제 공용 서비스 개발 계획

2026-10-17. 0.4 목업 이후 실제 서버 개발. 사용자 승인: 개발·테스트·리뷰 라운드까지 진행.

**상태 범위:** 아래 완료 표시는 0.5 공용 서버 기반과 읽기 전용 MVP에 한정한다. 코드 수정·테스트 실행의 현재 상태는 위 0.6 결과를 따르며, 배포별 실연결과 공동 사용은 [시범 운영 가이드](PILOT_GUIDE.md)로 확인한다.

완료 기준은 두 계정이 같은 업무방을 이용하고, 책임을 인계하며, 웹을 닫거나 서버가 재시작되어도 업무·기억·산출물이 유지되는 것이다. AI 제공자 연결과 실제 외부 계정 검증은 별도의 증거로 기록한다.

| 단계 | 작업                                                                | 통과 기준                                                    | 상태                    |
| ---- | ------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------- |
| 1    | 고정 소스·실행 환경 확인, Paperclip/Hermes 재사용 결정, 독립 리뷰 1 | 기존 제어면 중복과 권한 우회가 없는 구현 경계                | 완료 · ADR 001          |
| 2    | PostgreSQL migration, 계정·세션·부서/개인 ACL, 스킬 버전            | 두 사용자 권한·승격·충돌·중복 요청 통합 검사                 | 완료 · 검증 보고서 참조 |
| 3    | 유일한 업무/Run 큐, Worker 임대·세대·결과·재개                      | 중복 점유·구 Worker·재시작·스킬 변경 회귀 검사               | 완료 · 검증 보고서 참조 |
| 4    | 읽기 전용 모델 adapter, 근거와 기억, 한 업무의 검토→QA→수용         | HTTP 계약 검사·fixture 구분. 실제 모델 키/도구 하네스는 별도 | 완료 · 검증 보고서 참조 |
| 5    | 실제 로그인·오피스·업무방·기억·스킬·관리 UI                         | 서로 다른 브라우저 계정의 실시간 공동 사용                   | 완료 · 검증 보고서 참조 |
| 6    | Compose·마이그레이션·health·백업/복원·운영 문서                     | 로컬 Docker 기동·빈 DB 복원·운영 경로 점검                   | 완료 · 검증 보고서 참조 |
| 7    | 독립 리뷰 2/3, 수정, 전체 회귀·CI·공개 문서                         | 중대한 미해결 결함 없음, 검증 범위와 남은 연결 명시          | 완료 · 검증 보고서 참조 |

리뷰 발견과 수정 증거는 이 문서와 후속 리뷰 보고서에 연결한다. 한 번의 성공이나 테스트 fixture를 실제 모델·실계정 실행 증거로 사용하지 않는다.
