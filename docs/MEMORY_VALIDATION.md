# 장기 기억 목업 검증

아래는 2026-10-15의 단일 HTML/위젯 목업 검증 기록이다. 공개 웹 앱의 localStorage 기반 복원과 현재 검사 결과는 [후속 구현과 검증](IMPLEMENTATION.md)을 기준으로 한다. 아래의 위젯 저장 용량 제약은 현재 웹 앱의 제한을 뜻하지 않는다.

검증일: 2026-10-15. 대상: `agent-workspace.html`을 로컬 미리보기로 실행한 데스크톱 브라우저. 모든 대화·업무 결과·기억은 시연 데이터다.

| 항목 | 실제 확인한 결과 |
| --- | --- |
| QA 에이전트 검색 | 린이 읽을 수 있는 4개 기억 중 질문에 맞는 2개를 선택. 린의 경험과 팀 공통 규칙을 출처와 함께 표시 |
| 개발 에이전트 검색 | 카이의 수정 경험 + 개발 부서 계약 + 팀 공통 규칙 3개를 인용. QA 에이전트의 경험은 인용하지 않음 |
| 개인 대화 → 기억 | 로프레의 비서에게 시연용 고유 내용을 “기억해줘”로 저장한 뒤 다시 질문해 출처와 함께 회수 |
| 사용자 분리 | 민지로 전환한 뒤 같은 고유 내용을 질문했을 때 관련 기억 0개. 로프레의 개인 기억은 노출되지 않음 |
| 공용 대화 유지 | 민지가 카이에게 한 질문과 응답이 로프레로 계정 전환한 뒤에도 공용 대화에 남음 |
| 정정과 재로드 | 시연 기억을 v1에서 v2로 정정한 후 브라우저 새로고침. 현재 내용과 이전 버전·출처 유지 |
| 인용 버전 보존 | v1을 사용해 답한 뒤 기억을 v2로 수정. 과거 답변의 출처 링크가 “이전 버전 v1”과 당시 원문을 열고, 현재 기억으로 이동 가능 |
| 삭제 후 재로드 | 시연으로 만든 기억을 삭제하고 새로고침한 뒤 검색 결과 0개 확인. 테스트용 기억은 정리함 |
| 절차 → 스킬 | 제이의 결제 경계 조건 기억에서 스킬을 생성. 제이의 스킬 2개가 3개가 되고 해당 절차가 장착됨. 재로드 후 기억에 “연결된 스킬 보기” 표시 |
| 기존 오피스 | 4개 부서와 8명, 작업 진행·확인 대기 상태 유지. 타이핑·읽기·손동작·확인 말풍선 애니메이션 이름 확인 |
| 데스크톱 배치 | 1024×900에서 앱 너비와 scrollWidth 모두 992px. 버튼·입력·선택 컨트롤의 가로 넘침 없음. 기본 1280px 화면도 시각 확인 |
| 실행 오류 | 최종 브라우저 error 로그 빈 배열 |
| 정적 검사 | JavaScript 문법 검사 통과. HTML fragment, 스크립트 1개, 제품 CSS 변수 누락 없음, fetch/XHR/WebSocket 호출 없음. 전체 크기 1MB 미만 |

모바일은 요청 범위에서 제외했다. 임시 뷰포트 변경은 검증 후 원래 크기로 되돌렸고, 미리보기는 린의 기억 보관함과 검색 결과를 보여주도록 남겼다.

검증하지 않은 항목:

- 실제 API·모델·임베딩·자동 기억 추출 및 장기 원문 보관.
- 서버의 사용자 인증·ACL, 동시 갱신, 작업자 재시작과 운영 백업 복구.
- 장기간 데이터 증가에 따른 검색 정확도·응답 지연·비용.
- 16KiB 데모 상태 저장 한도를 실제로 초과시키는 대량 입력 실험. 한도 초과 시 현재 화면에만 유지됨을 표시하는 분기는 코드에 있지만 부하 검증은 하지 않았다.
- 초기 샘플 항목 삭제 후 재구성을 막는 삭제 ID 처리는 코드에 반영했으며, 브라우저에서는 직접 추가한 시연 항목의 삭제·재로드만 검증했다.

이 결과는 **인터랙티브 목업 검증**이다. 실제 서비스의 무제한 기억이나 다중 사용자 보안을 입증하지 않는다. 서버 설계와 후속 검증 시나리오는 [MEMORY_ARCHITECTURE.md](MEMORY_ARCHITECTURE.md)에 있다.
