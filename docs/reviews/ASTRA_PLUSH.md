# Astra · 0.15.0 캐릭터와 개발 일지 리뷰

2026-10-21. 기존 Astra 리뷰어에게 읽기 전용 재검토를 요청했다. **수정 후 미해결 필수 P0/P1/P2 없음**으로 승인했다. 최초 커스텀 캐릭터 P2와 수정·재검토를 아래에 보존한다.

## 발견과 수정

개발 동료의 ID만 보고 수달 장면을 선택하면, 기존 데모에서 카이를 토끼로 바꿨을 때 작은 초상과 큰 작업 장면이 달라진다. canonical 캐릭터가 수달인 카이에게만 전용 12장면을 적용하고, 다른 모습에서는 선택한 초상과 같은 개발 일지 상태를 표시하도록 수정했다. 이전 `cat` 저장값과 서버의 `dev` preset은 수달로 해석한다.

집중 단위 검사에서 기본·이전 ID·토끼·거북이·여우와 renderer의 대체 초상을 확인한다. 브라우저에서는 토끼 저장 → 오피스와 일지 일치 → 새로고침 유지 → 수달 복귀 후 두 장면 복원을 확인했다. 기존 캐릭터 선택 기능은 유지된다.

추가 수동 다크 모드 검수에서는 기존 접수 배너의 고정 밝은 배경과 밝은 글자가 겹치는 문제를 발견했다. 기존 라이트 색은 유지하고 다크 배경을 지정하는 CSS 한 줄을 추가했다. 리뷰어가 그 diff와 다크 캡처를 별도로 승인했다.

## 검토 범위와 증거

- 44개 동결 파일의 해시·bundle을 검토 전후 대조했다. 수정본 bundle은 `2b483df979a511705f7c5edd0e759ab6fda766abe1973f139a4e564f4f4e3b78`이다. 이후 다크 배너 CSS 1개를 별도로 검토해 총 45개 범위를 승인했다.
- 현재 Run의 행동만 선택하는지, Task 실패·대기 우선, 현재 artifact·대상 버전·native 종료·성공 검사 근거, 요약/외부 결과의 성공 오인 방지를 확인했다.
- 이전 캐릭터 ID와 실제 서버 역할 preset, HTML escape, 모션 제어, 기존 스킬 작성 화면의 submit 버튼 포커스 보존을 확인했다.
- 오피스·12장면 디자인 시트·서버 업무방 PNG 세 개를 직접 보았다. 이웃 장면 혼입·찌그러짐·가짜 통과 표시는 발견하지 않았다. 이후 다크 PNG도 확인했다.
- 독립 실행은 `tests/work-diary.test.js`와 `tests/office-station.test.js`의 **7개 통과**다. 같은 7개 재실행은 전체 검사 수에 더하지 않는다. 추가 다크 변경 검토에서는 독립 테스트 0개다.

리뷰어는 전체 DB·Docker·브라우저 검사를 다시 실행하지 않았고, GIF 전체 프레임과 실모델 업무 품질을 판정하지 않았다. 작성자의 최종 72/157/6/32/24 및 복원 결과는 [검증 기록](../SERVER_VERIFICATION.md)에 별도로 있다.
