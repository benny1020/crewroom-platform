# Astra 장기 운영 리뷰 · 0.11.0

2026-10-19, gpt-6-astra의 독립 읽기 전용 리뷰. [검토한 20개 파일의 SHA-256](../evidence/0.11/reviewed-files.json), manifest hash `e7573983936d2522a19b5741664158355708407dcb683667618bcbc6771b750a`에 결부된다. 문서·미디어 변경은 소스 동결과 별도로 관리한다.

초기 설계 리뷰는 keyset의 microseconds/bigint, 현재 결과·생성 Run 고정, 이벤트 ID 발급과 commit 순서 차이, 원문 ACL/수정 재검사, Runner 정리 전 종료 확인과 재시도 원장을 요구했다.

중간 코드 리뷰의 P2 세 건을 수정했다.

1. 의미 검색 용량 사전 조회와 벡터 읽기 사이 indexer 경쟁: 단일 SQL snapshot의 용량 판정과 조건부 읽기로 변경했다. 초과 시 일부 corpus를 정상 의미 검색으로 표시하지 않는다.
2. 운영 통계가 문서 수만 판정: 좌표 수·직렬화 바이트 합계까지 실제 검색과 같은 기준으로 표시한다.
3. 후보 검색 뒤 원문 정정 시 이전 검색 점수 재사용: 후보 내용 fingerprint를 원본과 비교하고 현재 project/before/asOf/agent/ACL/의존 근거를 재검사한다.

최종 리뷰에서 **검토 범위의 남은 필수 P0/P1/P2를 발견하지 못했다.** 리뷰어는 검토 파일 20개와 규모 측정의 소스 6개 hash가 현재 파일과 일치함을 확인했다. 별도의 임시 DB schema에서 이력·이벤트·장기 운영 검사 **11/11**, 실패·skip 0을 직접 확인했다. 문서 수 이내에서 좌표/바이트만 초과하는 경우 검색·통계·indexer가 모두 전환되고 외부 호출은 0회임을 확인했다. 이 집중 검사는 전체 자동 검사 수에 중복 합산하지 않는다.

규모 측정은 100,001개 업무·100만 메시지의 합성 데이터에 대한 로컬 증거다. 실제 모델·embedding 품질·수년 운영·PITR/ANN/HA를 검증한 것으로 확대하지 않는다. 최종 공개 커밋의 CI는 별도로 확인한다. [구현 경계](../LONG_TERM_OPERATIONS.md) · [전체 검증](../SERVER_VERIFICATION.md)
