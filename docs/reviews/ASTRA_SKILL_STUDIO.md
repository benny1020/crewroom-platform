설계·초기 코드와 구현 후 재리뷰에서 아래 경계를 보강했다.

| 검토 사항 | 반영 |

| 일반 업무 생성과 저장·적용의 잠금 역순 후보 | context gate 순서 통일. 같은 동료·스킬의 동시 생성·저장을 barrier로 맞춘 회귀 통과. 실제 deadlock을 재현했다고 확대하지 않음 |
| 첫 AI 응답 실패 후 수동 저장한 설계의 이어가기 차단 | 검증된 canonical draft가 있는 skill-design에만 Artifact 없는 새 Run 허용. 일반 대화 조건 유지 |
| 업무방 질문 답변·재작업이 snapshot에는 있고 HTTP 본문에서는 누락 | 고정 questions/rework/brief 전달. 재작업 후 정정한 최신 요약까지 실제 발송 본문 marker 확인 |
| 실제 예시 입력 대신 모델의 추천 입력을 표시하는 문제 | 서버가 Run의 sampleInput 저장. 해당 Run·같은 초안의 출력과 실제 입력을 짝지어 표시 |

첫 응답 실패 복구와 질문/재작업 누락은 리뷰어가 임시 DB schema에서 직접 재현했다. 예시 표시 문제는 코드 검토 후 실제 `studioView` 함수로 실제 입력 표시·새 요청 실패 시 이전 출력 숨김·초안 변경 시 이전 출력 숨김의 세 경계를 별도 확인했다. 이는 브라우저 검증과 구분한다.
