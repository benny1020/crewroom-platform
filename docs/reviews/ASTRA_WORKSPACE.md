## 기획과 조사 결정

DB에 이름 있는 영속 문서·불변 버전·출처를 두고 기존 행동 루프에 연결한다. App/Worker/Runner 책임은 유지한다. 에이전트 홈은 사용자 권한에 맞는 task 문서 모음이다. 새 파일시스템 프레임워크·FUSE·전용 agent 컨테이너·외부 에이전트 SDK는 추가하지 않는다. 초안은 자동 공식 기억이나 승인된 스킬이 되지 않는다. [공식 자료·논문·실제 공개 코드 근거](../AGENT_WORKSPACE.md#조사와-리뷰에서-선택한-방식).

## 발견과 반영

| 검토 내용 | 반영 |
| --- | --- |
| 자체 작성 문서 출처를 없애면 이후 정정이 파생 답변에 전파되지 않음 | 원래 관찰 기록과 현재 기대 버전을 분리하고 최종 답변에 문서 revision을 고정 |
| 같은 실행의 모든 문서를 출처에서 빼면 A→B 의존성이 사라짐 | 직접 self만 제외; 간접 의존성을 바꾸는 저장은 전체 read-set 검사 후 rollback |
| 과거 답변 주입과 현재 문서 수정이 충돌 | 현재 문서를 도구로 다시 읽고 이어감; 옛 답변 UI 유지, 자동 본문 주입 경계 명시 |
| QA·재작업에 전달한 파생 본문의 출처 누락 | 실제 제공 section의 key·본문·출처 모두 고정하고 문서·결과에 상속 |
| summary만 정정된 경우 다른 section 존재로 옛 본문이 살아남음 | 원본 result의 모든 nonempty section을 대조; 하나라도 원문이 없으면 시작 거절 |
| 보관 문서가 기억 제안으로 재사용됨 | workspace kind의 기억 제안을 명시적으로 거절 |
| 버전 이름에 저장형 HTML이 들어갈 수 있음 | 경로 escape와 브라우저 회귀 |
| 조회 중 저장으로 본문과 표시 revision이 달라질 수 있음 | HTTP 문서 조회를 context gate 트랜잭션으로 직렬화 |
| 코드 루프에서 복구 가능한 문서 충돌이 즉시 실패함 | 분석·코드 공통 오류 receipt로 반환, 권한/출처 취소는 종료 유지 |
| 새 배포에서 이전 이미지 tag를 찾는 검증 스크립트 | 실제 Compose app image를 사용하고 미래 릴리스 회귀와 Linux 소유권 재검증 |
| 응답 유실 후 중복 저장 | Run/generation/operation fingerprint와 저장 receipt로 멱등 처리 |

핵심 코드 16개 승인 후 화면·실행 fixture·배포·복원·시연 파일까지 확장한 **30개 동결 파일**도 추가 P0/P1/P2 발견 없이 승인했다. [현재 동결 범위](../evidence/0.14.0/reviewed-files.json)의 검토 종료 hash 재대조도 일치했다. 묶음은 `34cc07eaf680f01351ee3fd145fb5ac94a598a009ae5f1805f6d660ebf1f520f`이다. 최종 커밋 연결은 GitHub 검증 기록과 함께 확인한다.

## 남은 제품 경계

현재 웹 문서 뷰는 조회·검색·이전 버전을 제공한다. 사람의 직접 문서 편집·보관 UI와 자동 의존 문서 재작성은 포함하지 않는다. 정정으로 무효화된 출처를 새 revision으로 조용히 바꾸지 않고 현재 자료로 후속 문서를 작성한다. 예약·이벤트 기반 자동 업무 시작도 이번 범위 밖이다. 실제 모델의 문서 관리 효용, 비용, 같은 모델에서의 CLI 수준 품질은 이번 코드 리뷰로 입증하지 않는다.
