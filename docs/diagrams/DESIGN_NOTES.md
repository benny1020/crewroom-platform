# 아키텍처 도식의 조사 근거와 표현 규칙

2026-10-17. 목표는 처음 보는 팀원도 **어떤 서비스가 상주하는지, 데이터가 어디에 남는지, 코드가 어디에서 실행되는지** 읽을 수 있게 하는 것이다. 아래 공식 문서의 표현 방식을 조사해 현재 0.8 구현에 맞춰 적용했다. 특정 도구의 사용률 순위나 새롭게 등장한 표준이라는 의미는 아니다.

C4의 container는 애플리케이션·데이터 저장소라는 **논리적 단위**다. Docker 컨테이너와 혼동하지 않도록 실제 프로세스와 Docker 실행 경계는 [실행 구조](execution-architecture.svg)에서 따로 설명한다. 기본 Compose는 같은 Docker Engine을 사용하며 Runner를 별도 실행 host/VM에 배치할 수도 있다.

## 시각 표현 규칙

- **아이콘 + 이름 + 역할**을 함께 표시한다. 브랜드 로고만으로 기술을 추측하게 하지 않는다.
- 구조도의 보라는 업무 처리 서비스·실행 문맥, 초록은 영속 데이터, 파랑은 외부 연결, 황토색은 코드 실행·검증을 나타낸다. 조직도에서는 같은 팔레트를 부서에 배정하며 그림마다 범례로 뜻을 명시한다. 색상은 성공·실패 상태를 뜻하지 않는다.
- 큰 연한 배경은 소유·배치 경계이고 흰 상자는 개별 요소다. 화살표는 요청·데이터 전달·업무 인계의 방향이다. 전체 구조도의 점선은 SSE 갱신 알림이다. 단순 요청선에 응답 화살표까지 겹쳐 넣지 않는다.
- 순서를 설명하는 업무 흐름에만 단계 번호를 사용한다. ERD와 상세 시퀀스는 해당 표기법을 유지한다.
- 기본 캔버스는 폭 1280px이다. 제목 32px, 요소명 20–22px, 본문 20px, 보조 기술명 16px을 사용한다. 한글 줄바꿈을 직접 지정하고 글자가 상자를 벗어나면 생성 단계에서 실패시킨다.
- PNG는 2배 해상도로 저장해 GitHub 본문에 표시하고, 누르면 확대 가능한 SVG를 연다. 외부 폰트·아이콘 CDN·스크립트를 SVG에 넣지 않는다.

## 구현과 검증

핵심 도표는 `source/*.json`에서 `scripts/illustrated-diagrams.mjs`로 SVG를 생성한다. 나머지 ERD·시퀀스·이전 설계 기록은 `source/*.mmd`에서 Mermaid로 생성한다. Chromium은 두 형식을 PNG로 내보내는 데 사용한다. 도구 이름을 보여주는 대신 결과 이미지를 문서에 삽입한다.

[도표 수정 안내](README.md)의 명령으로 전체 30개를 다시 생성할 수 있다. `manifest.json`은 편집 원본·렌더러·아이콘 라이선스·의존성 lock 파일·이미지의 SHA-256을 기록한다. 문서 검사는 생성 누락·변경된 이미지·깨진 로컬 링크·본문의 Mermaid 코드 블록을 거절한다. 도표는 현재 코드의 설명이며, 외부 모델 추론이나 배포 환경의 정상 동작을 대신 검증하지 않는다.
