# Claude custom endpoint boundary

Crewroom reuses Paperclip's `claude_local` adapter and normal task/wake/run services. It does not introduce an additional execution engine. Adapter-specific environment configuration accepts `ANTHROPIC_BASE_URL` and API authentication, and `packages/adapters/claude-local/src/server/execute.ts` carries the configured environment into execution. Managed connection secrets should use upstream connection/secret references; do not put API keys in checked-in configuration, shell commands, task text or chat.

For an authorized custom endpoint, configure the upstream Claude connection and the agent's adapter/runtime settings, select a compatible model and target workspace, then run its existing environment test. The endpoint must implement the protocol expected by the selected Claude harness; an arbitrary OpenAI-compatible URL is not automatically compatible. Follow that provider's model and authentication contract. Do not disable permission checks or substitute BoardChat to force a successful reply.

Observed locally on 2026-10-28: `claude --version` returned `2.1.126 (Claude Code)`. `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` and external `DATABASE_URL` were unset; only presence was inspected. The isolated instance has no provisioned model credentials, no live endpoint test and no real model response. The JWT signing secret is also unconfigured, so agent control-plane authentication still needs official onboarding before execution.

Focused upstream fixture checks (`probe-env.test.ts` and `test.probe.test.ts`) passed 27 tests, covering selected environment/probe behavior. They do not prove a custom proxy, account login, inference, persistent continuation, cost accounting or production isolation. Live acceptance must separately retain the actual environment-test result, normal task/run receipt, persisted response, cancellation and subsequent continuation under the same authorized account, without exposing credentials.
